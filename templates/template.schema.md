# Template schema

A template is one JSON file. It declares what should exist — it never contains imperative
generation steps; those belong to the agent (Maker) that reads it during a PMCR-O cycle.

```json
{
  "template": "skill | plugin | agent | product",
  "name": "kebab-case-name",
  "version": "1.0.0",
  "description": "One line, shown in the marketplace.",
  "vars": {
    "<var_name>": {
      "type": "string | boolean | number | enum",
      "required": true,
      "default": "optional default value",
      "options": ["only for type: enum"]
    }
  },
  "declares": {
    "files": [
      {
        "path": "output/relative/path/with/{{var_name}}/tokens.ext",
        "body_ref": "id of a body block below, or omit to have the agent draft it from `description`"
      }
    ]
  },
  "requires_trail": true,
  "laws": ["EC-SYS-003", "EC-VERIFY-FIRST-001", "EC-004", "EC-009", "EC-PORTABLE-005"],
  "interception_points": ["pre_tool_call", "post_tool_call"]
}
```

## Fields

- **`template`** — which of the four kinds this produces (`skill`, `plugin`, `agent`, `product`).
  A `product` template's `declares.files` typically references other templates rather than raw
  file bodies — see `examples/product.template.json`.
- **`vars`** — the inputs a person or a calling agent must supply. `{{var_name}}` inside any
  `path` or generated body is replaced with the supplied value. Unresolved required vars are a
  generation error, caught by the Checker, not silently defaulted.
- **`declares.files`** — the complete list of paths this template can produce. The Checker's job
  on a generation trail is to confirm every listed path exists and, where a `body_ref` is given,
  that its content matches — nothing more, nothing improvised.
- **`requires_trail`** — always `true` in practice; kept explicit because a template is the one
  place `pmcro` could theoretically be misused to bypass Law 1, and this field makes that
  impossible to do quietly.
- **`laws`** — the specific law IDs (from `docs/governance/laws.md`) a Checker must verify against for this
  template. Most templates bind all five; a narrower template may bind fewer.
- **`interception_points`** *(optional)* — which of the eight MAF-aligned interception points
  (`docs/governance/interception-points.md`) the generated skill/agent instruments. Omit it to instrument
  all eight (the default for `plugin` and `product` templates); a narrow `skill` template
  typically names just `pre_tool_call`/`post_tool_call`.

## Naming

`name` must be unique within its `template` kind. A `product` named `tooensure-<x>` scaffolds a new
installable product the same way `pmcro` itself was scaffolded — company products and marketplace
plugins are generated by the same mechanism, just at a different `template` kind.
